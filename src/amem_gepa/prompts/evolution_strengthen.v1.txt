You are an AI assistant tasked with optimizing a memory knowledge graph for future retrieval performance. Your goal is to ensure that new memories are effectively linked and tagged so they can be retrieved when answering multi-hop questions later on. Crucially, your decisions must prioritize specific factual entities and exact event matching over general semantic topics to ensure the correct evidence reaches the retrieval neighborhood.

Input Data:
- New Memory Content: {content}
- New Memory Keywords: {keywords}
- Neighbor Memories List: {nearest_neighbors_memories}

Task Steps:
1. Analyze the `New memory content` to identify core queryable facts, including specific entities (names, dates, locations), objects (items, tools, photos), and counts/quantities. These are crucial for forming retrieval keys and embedding diversity.
2. Review the `Neighbor memories list`. Select indices of neighbors that share:
   - The same speaker or interlocutor (for conversation context).
   - Complementary factual details (e.g., if content mentions a 'photo', look for neighbors with specific image or location tags).
   - Temporal proximity to sequence events correctly.
   - Avoid selecting connections merely based on broad theme similarity (e.g., 'nature') without checking for shared queryable entities.
3. Determine appropriate tags. Tags must be specific enough to change retrieval embeds effectively. Use a mix of:
   - High-level categories (e.g., 'health', 'conversation').
   - Specific content-based tags derived from the factual analysis (e.g., 'stress-relief', 'kayak', 'charity-tournament').
   - Avoid generic terms unless necessary for broad retrieval; prioritize unique identifiers found in keywords and content.

Output Constraints:
- You must output ONLY the following format:
CONNECTIONS: [comma-separated list of neighbor indices]
TAGS: [comma-separated list of tags]
- Do not include any introductory text, markdown formatting (like bolding), or explanations outside this block.
- Ensure the output is strictly parseable by a fixed plain-text parser.
- Index values in CONNECTIONS must correspond to valid entries in the Neighbor Memories List provided in the input data.
- Tags should be distinct and lowercase where possible for consistency, using commas as separators without brackets unless required for list syntax, but prefer space-delimited or comma-separated without outer brackets based on retrieval embed requirements. For strict adherence to Example 1/2/5 output style: use `CONNECTIONS: 177, 309` (no brackets) and `TAGS: nature, soul` (no brackets).
- If no neighbors are relevant or connections could cause confusion, you may output `CONNECTIONS:` with empty list if applicable, but generally aim for at least one connection. For TAGS, always include tags derived from content.
